# 게임 콘텐츠 로드맵과 첫 조각(집 짓기) 설계

> 상태: **조각 1(집 짓기)은 서버와 Unreal C++ 구현을 마쳤고(Windows), 에디터 에셋(MCP)과 PIE 확인이 남았다.** 조각 2~6은 계획이며, [game-plan.md](game-plan.md)를 스타듀밸리 풍(하루 루프, 농사, 출하와 상점, 제작과 도구 강화)으로 다시 짠 뒤 순서를 고쳤다. 4단계 확장 1(자원 채집, [stage4-gather.md](stage4-gather.md))이 끝난 뒤의 콘텐츠 계획이다. 조각 1의 합격 기준은 구현 전에 쓴 것이고 구현 뒤의 검증 결과는 "조각 1 검증 결과"에 있다. 사용자가 정한 것과 임의 기본값을 구분해 적었다. 각 조각은 구현 전에 이 문서의 해당 절을 확정하고 합격 기준을 먼저 쓴다. 값은 `PlayConfig` 한 곳에서 바꾼다. 문서에는 날짜를 쓰지 않는다.

## 목표 루프

지금은 "움직인다 → 자원을 모은다 → 집을 짓는다"에서 끝난다. 게임다운 하루는 아래 루프가 돌아야 한다.

```
아침 ─▶ 밭 갈기·심기·물 주기 / 채집 ─▶ 수확 ─▶ 출하 상자 ─▶ 잠 ─▶ 밤 정산(성장, 판매 → 공용 돈, 재생, 완공, 저장)
  ▲                                                                                     │
  └──────────── 상점(씨앗 사기, 도구 강화), 제작(스프링클러), 집 짓기 ◀───────────────────┘
```

1~4명이 함께 하는 협동 게임이므로 "누군가 모으고, 누군가 짓고, 함께 키운다"가 자연스럽게 나뉘어야 한다. 이 문서는 서버가 상태와 판정을 소유한다는 기존 원칙(클라이언트는 의도만 보낸다)을 그대로 따른다.

## 조각 순서

| 조각 | 내용 | 서버에 새로 필요한 것 | 크기 |
| --- | --- | --- | --- |
| **1 집 짓기** | 목재/석재로 집을 짓는다. 건물과 나무/돌이 이동을 막는다 | 구조물 상태, 배치 판정, **이동 충돌**, 건설 진행 | 큼 (완료) |
| 2 하루와 잠 | 게임 시계(06:00~02:00, 10분 = 하루), 잠자기/깨어나기, 모두 잠들면 밤 정산, **채집 재생과 건설 완공을 밤 정산으로 옮김**, 시계 저장 | 시계, 잠 상태, 밤 정산 단계(정해진 순서의 결정적 계산), 기존 틱 기반 재생/완공의 교체 | 중간 |
| 3 아이템 일반화와 농사 | 일반 아이템 표, 밭 갈기, 심기, 물 주기, 하루 성장(물 준 칸만), 수확, 처음 씨앗 지급 | 칸 단위 밭 상태, 칸 대상 행동 판정, 바뀐 칸 알림, 아이템 표와 저장 | 큼 |
| 4 경제 | 농장 공용 지갑, 출하 상자(밤에 판매), 상점(씨앗 사기) | 지갑, 출하 상자 내용, 가격표, 구매 판정, 저장 | 중간 |
| 5 제작과 도구 강화 | 도구 3단계 강화(상점), 스프링클러 제작(밤 정산 때 물 주기, 이동을 막음) | 도구 단계(개인), 레시피, 새 장애물 | 중간 |
| 6 다듬기 | 소리, 애니메이션, 캐릭터, 에셋 교체, UI, 카메라 가림 | (거의 없음) | 계속 |

이전 계획의 "5 월드 저장"은 계정과 농장 저장([persistence.md](persistence.md))이 먼저 들어오면서 없앴다. 대신 조각 2~5가 **각자 새 상태의 저장**(시계, 밭, 아이템, 지갑, 출하 상자, 도구, 스프링클러)을 포함하고, 저장 시점에 "밤 정산"을 더한다.

병행 가능한 서버 쪽 일(콘텐츠와 무관): 저장 부하 측정(persistence.md P4), Linux 빌드 확인, 느린 연결의 스냅샷 처리. 부하 재측정은 조각 1 직후(했음)와 조각 3 직후에 한다. 조각 2부터는 **밤 정산 한 틱의 처리 시간**도 따로 잰다(정산이 무거우면 그 틱에 스냅샷이 밀린다).

각 조각은 채집과 같은 순서로 만든다: **S0 서버(프로토콜, 로직, 시험, 변형 검증) → S1 Unreal C++(에디터 닫음) → S2 MCP 에셋(에디터 엶) → S3 사람이 PIE로 확인**.

### 이월하는 설계 부채

- **채집 재생(30초)과 건설 시간(5초)이 틱 기준**이다. 조각 2에서 밤 정산으로 옮긴다. 저장된 건설 중인 집의 `remaining_ticks`는 "다음 밤 정산에 완공"으로 뜻이 바뀌므로 조각 2에서 마이그레이션 방법을 정한다.
- **인벤토리가 `wood`/`stone` 두 칸**이다. 조각 3에서 작물이 들어오면 일반 아이템 표(번호와 개수)로 바꾼다. 프로토콜은 하위 호환으로 `repeated ItemCount`를 더하고 기존 `wood`, `stone` 필드는 한동안 같이 채운다. 조각 1에서는 건드리지 않는다.
- 노드가 **통과 가능**하다. 조각 1에서 충돌을 넣으면서 함께 해결한다.

## 조각 1: 집 짓기

### 범위

포함
- 집 한 종류. 플레이어가 B 키로 건설 모드에 들어가 놓을 곳을 고르고 확정한다
- 비용은 건설을 요청한 플레이어의 **개인 인벤토리**에서 즉시 차감한다
- 건설은 즉시 끝나지 않고 짧게 "건설 중" 상태를 거친다(진행은 서버 틱으로 센다)
- 구조물과 노드(고갈되지 않은 나무, 돌)가 **이동을 막는다**(서버 판정, 방 안 모든 사람이 같은 결과)
- 늦게 입장한 사람도 지금 있는 구조물을 받는다

제외(필요해지면 다음에)
- 철거, 이동, 업그레이드, 여러 종류의 건물, 문과 실내(집은 속이 찬 직사각형 장애물)
- 여러 사람이 비용을 나눠 내는 공동 건설 현장, 방 공용 창고
- 건물 안 가구, 지붕이 시야를 가릴 때의 투명 처리(카메라가 가려지면 조각 6에서)
- 저장(조각 5), 소리와 건설 애니메이션

### 기본값 (`PlayConfig`, 모두 임의 기본값)

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 집 크기 | 300 x 300 cm | 축에 정렬된 직사각형, 중심 좌표로 다룬다 |
| 비용 | 목재 20, 석재 10 | 나무 4그루, 돌 2개 정도. 채집 기본값(나무 체력 5, 돌 8)으로 몇 분 안에 모을 수 있게 잡았다 |
| 배치 격자 | 100 cm | 서버가 요청 좌표를 격자 중심에 맞춘다(건물이 어긋나게 쌓이는 것을 막는다) |
| 배치 가능 거리 | 내 위치에서 500 cm 이내 | 서버 위치 기준 |
| 건설 시간 | 100틱(5초) | 이 동안 "건설 중"이며 충돌은 처음부터 있다 |
| 방당 구조물 상한 | 20개 | 메모리와 남용 방지 |
| 노드 충돌 크기 | 반지름 60 cm 원 | 고갈된 노드는 막지 않는다 |
| 플레이어 | 반지름 40 cm 원(기존) | 구조물, 노드와만 충돌하고 플레이어끼리는 통과(기존 규칙 유지) |

### 프로토콜 (`proto/game.proto`, 하위 호환으로 더한다)

| ID | 메시지 | 방향 | 설명 |
| ---: | --- | --- | --- |
| 113 | `BuildRequest{structure_type, x, y}` | C→S | 그 자리(격자로 맞춰짐)에 짓고 싶다 |
| 114 | `BuildResponse{result, structure_id, wood, stone}` | S→C | 결과와 내 인벤토리 |
| 115 | `StructureUpdate{tick, structures[]}` | S→C | 새로 생기거나 상태가 바뀐 구조물(방 전원). 바뀐 것이 있는 틱에만 |

추가: `RoomState.structures = 6`(`repeated Structure{structure_id, type, x, y, width, height, state, ready_tick}`), `StructureType`(`STRUCTURE_HOUSE = 0`), `StructureState`(`BUILDING = 0`, `COMPLETE = 1`). 결과 코드: `GAME_BUILD_INVALID_TYPE = 13`, `GAME_BUILD_BLOCKED = 14`(겹침, 맵 밖), `GAME_NOT_ENOUGH_RESOURCES = 15`, `GAME_BUILD_TOO_FAR = 16`, `GAME_STRUCTURE_LIMIT = 17`, `GAME_BUILD_OUT_OF_ZONE = 18`(건설 구역 밖, "구역 분리" 절).

판정 순서(처음 걸리는 것): 방에 없음 → 종류 모름 → 구조물 상한 → 너무 멂 → **건설 구역 밖** → 겹침/맵 밖 → 자원 부족. 거부는 상태를 바꾸지 않는다. 겹침 검사 대상은 맵 경계(구조물 전체가 맵 안), 기존 구조물, 고갈되지 않은 노드, **방 안의 모든 플레이어**(플레이어 몸 위에 지으면 갇히므로 거부)다. 성공하면 비용을 차감하고 `BUILDING` 구조물을 만든 뒤 `ready_tick`을 정하고, 틱 끝에 `StructureUpdate`가 방 전원에게 간다. `ready_tick`에 `COMPLETE`로 바뀌고 다시 알린다.

### 이동 충돌 (`World`)

이 조각에서 가장 위험한 부분이다. 현재 `World::Step`은 맵 경계만 처리한다.

- 장애물 목록(직사각형과 원)을 받아, 한 틱 이동량(18 cm)을 **축별로 나눠 적용**한다(x를 옮겨 보고 막히면 되돌리고, y도 같게). 벽을 따라 미끄러지는 느낌이 나고 구현이 단순하다.
- 한 틱 이동량이 가장 얇은 장애물보다 작으므로(18 cm < 120 cm) 뚫고 지나가는 일이 없다. 이 전제는 시험으로 확인한다.
- 같은 입력 열이면 같은 결과인 결정성을 유지한다(부동소수점 순서 고정).
- 플레이어가 이미 장애물 안에 있는 상태로 시작하는 일이 없도록 건설은 위의 겹침 검사로, 노드는 시작 영역을 비워 막는다. 그래도 겹쳐 있다면(예: 설정이 바뀜) 갇히지 않고 빠져나갈 수 있게 "이미 겹친 장애물과는 충돌하지 않는다"로 처리한다.
- 구조물과 노드 목록은 `Room`이 가지고 `World`에 읽기 전용으로 넘긴다. `World`는 계속 소켓과 시계를 모른다.

### 완료 기준 (구현 전에 확정)

서버
1. **배치 성공:** 범위 안의 빈 곳에 요청하면 `GAME_OK`, 비용이 차감되고, 격자 중심으로 맞춰진 `BUILDING` 구조물이 생기고, 방 전원이 틱 끝에 `StructureUpdate`를 받는다. 건설 시간이 정확히 지난 틱에 `COMPLETE`로 바뀌고 다시 알린다(99틱 아직, 100틱 완료).
2. **거부와 순서:** 방에 없음, 모르는 종류, 상한, 너무 멂(경계 포함: 500.0 허용), 겹침(기존 구조물, 노드, 플레이어, 맵 밖 각각), 자원 부족이 정해진 코드를 돌려주고 상태(구조물, 인벤토리)가 바뀌지 않는다. 판정 순서도 시험한다.
3. **자원 정확성:** 목재 19개나 석재 9개로는 지을 수 없고 20/10이면 지을 수 있다. 성공 뒤 인벤토리가 정확히 20/10만큼 줄고, 응답이 현재 값을 담는다. 두 사람이 같은 틱에 같은 자리에 지으려 하면 정확히 한 명만 성공한다.
4. **충돌:** 플레이어가 구조물과 고갈되지 않은 노드로 걸어 들어가면 막히고, 벽을 따라 미끄러지며, 모서리에서 끼지 않는다. 고갈된 노드는 통과한다. 재생하면 다시 막는다. 어떤 입력으로도 장애물 안으로 들어가지 못한다(방향을 부풀려도, 대각선 모서리에서도). 같은 입력 열이면 같은 위치다(결정성).
5. **격리와 입장:** 다른 방의 구조물에 영향이 없다. 늦게 입장한 사람은 현재 구조물(건설 중/완료)을 입장 응답으로 받는다.
6. **견고함:** NaN/무한대 좌표, 아주 큰 좌표, 나간 직후의 요청, 연결이 끊기는 중의 알림에서 죽지 않는다.
7. **기존 기능 유지:** 기존 `ctest`가 그대로 통과한다(이동 시험은 장애물이 없는 방에서 결과가 같아야 한다).
8. **변형 검증:** 거리 비교, 겹침 판정의 경계(한 칸 차이), 비용 비교(`>=`/`>`), 건설 시간 off-by-one, 충돌의 축 분리, 고갈 노드 처리, 플레이어 겹침 검사 제거 등을 고의로 심어 시험이 잡는지 확인한다.
9. **부하 재측정:** 충돌이 이동 계산 비용을 늘린다. **측정 전에** 합격 기준을 확정한다: 기존 게임 부하 측정([stage4.md](stage4.md))과 같은 절차와 같은 합격 기준으로, 방 500개가 여전히 합격해야 한다(합격 못 하면 그 최대 방 수를 새 결과로 기록하고 원인을 따로 본다). 구조물이 방당 상한(20개)까지 찬 워크로드도 함께 잰다. 재지 않은 수치는 주장하지 않는다.
10. **문서:** 이 문서, [stage4.md](stage4.md) 프로토콜 표, [unreal-client.md](unreal-client.md)에 기준 바이트.

Unreal
11. **자동 시험(`GameClientSpike`):** 진짜 서버에 대해 걸어가서 짓기, 비용 차감, 거부(자원 부족, 너무 멂, 겹침), 건설 중 → 완료 알림, 방 사람 모두의 구조물 목록, 늦은 입장자의 구조물 목록, **지은 벽 쪽으로 걸어가면 위치가 막히는 것**(스냅샷 위치로 확인), 나가면 비워짐.
12. **PIE(사람이 확인):** 창 2개에서 한쪽이 B로 놓을 곳을 보며 확정하면 다른 쪽 화면에도 건설 중 → 완성 집이 생기고, 두 사람 모두 집과 나무를 통과하지 못한다. 놓을 수 없는 곳은 빨갛게 보인다.

### Unreal 설계 (요약)

- `FGameClient`/`UYongNetSubsystem`: `Build(type, x, y)`, 구조물 목록, `OnBuildResult`, `OnStructuresChanged`, 인벤토리 갱신 재사용.
- `AYongStructureActor`: 구조물 하나의 표현. 건설 중이면 반투명 비계, 완료되면 완성 메시. 블루프린트 자식 `BP_House`가 메시를 정한다. 충돌 없음(판정은 서버).
- 건설 모드: B 키로 켜고 끈다. `AYongBuildGhost`(미리보기)가 내 앞 격자 중심을 따라가고, 클라이언트가 아는 정보(구조물, 노드, 거리)로 놓을 수 있는지 **대략** 계산해 초록/빨강으로 칠한다. 서버가 최종 판정이다. 왼쪽 클릭이나 Enter로 확정, Esc로 취소한다.
- HUD: 건설 모드일 때 비용 표시(선택 위젯, `BindWidgetOptional`)와 거부 문구.
- 서버 위치 기준 이동이므로 클라이언트 예측이 없다. 보간된 화면 위치가 벽에서 멈춘 것처럼 보이는 것은 서버 위치를 그대로 그리기 때문이며 별도 처리가 없다.

### MCP 작업 (S2, 에디터 작업만)

1. `BP_House`(부모 `AYongStructureActor`): 첫 에셋은 엔진 기본 도형으로 만든 임시 집(`Cube` 벽 + 지붕)이어도 된다. Kenney 건물 에셋은 라이선스를 확인한 뒤 교체한다.
2. 비계 머티리얼(반투명), 건설 미리보기용 초록/빨강 머티리얼.
3. `BP_YongRoomGameMode`에 `HouseClass`, 건설 미리보기 클래스 지정.
4. `WBP_HUD`에 비용 텍스트(`BuildCostText`), 건설 안내(`BuildHintText`) 추가(선택 위젯).

### 위험

- **충돌이 서버 이동의 핵심을 바꾼다.** 이동은 이 서버의 가장 많이 도는 코드다. 결정성과 성능(완료 기준 4, 9)을 가장 신중하게 다룬다.
- 노드를 막는 것으로 바꾸면 기존 PIE에서 나무를 "통과해서" 치던 동작이 달라진다. 채집 허용 거리(200 cm)가 충돌 반경(40+60=100 cm)보다 크므로 막혀도 칠 수 있다.
- 놓은 자리가 내 캐릭터를 가두는 일을 겹침 검사(모든 플레이어 포함)로 막는다. 대신 "다른 사람이 서 있어서 못 짓는" 일이 생긴다. 이것은 의도된 규칙이다.
- 집이 카메라 시야를 가린다(탑뷰에서 뒤에 있는 캐릭터가 가려짐). 조각 6의 일이다.

## 구역 분리 (자원 구역과 건설 구역)

**문제:** 노드가 재생할 때 구조물과 사람을 피해 새 자리를 고르는 규칙에서, 건물이 많아지면 노드가 설 자리가 부족해질 수 있다. 리젠을 없애면 자원 총량(목재 150, 석재 160)에서 끝나 집 7채 정도로 막힌다. 그래서 **리젠은 유지하고 구역을 나눈다.**

- **건설 구역:** 맵 중앙의 정사각형(중심에서 사방 1,200 cm, 한 변 2,400 cm = 맵의 약 23%). 건물은 **발자국 전체가 이 안**에만 들어갈 수 있다(경계에 닿는 것은 허용). 밖이면 새 결과 코드 `GAME_BUILD_OUT_OF_ZONE`(18)로 거부한다. 판정 순서는 너무 멂 → **건설 구역 밖** → 겹침/맵 밖 → 자원 부족이다.
- **자원 구역:** 구역 밖 나머지. 노드는 처음 배치와 재생 모두 **건설 구역(노드 충돌 반지름 60 cm만큼 넓힌 것) 밖**에만 놓인다. 건물은 구역 안에만 있으므로 재생 자리가 건물 때문에 줄지 않는다. 시작 영역(반지름 500 cm)은 건설 구역 안이라 따로 비우던 규칙은 그대로 두었다.
- `PlayConfig::build_zone_half_size_cm`(기본 1,200, **0이면 제한 없음**). 재생 자리를 못 찾으면 `respawn_retry_ticks`(기본 20, 1초)마다 다시 찾는다(이전에는 매 틱 최대 1,000번 시도했다).
- 클라이언트는 건설 모드에서 구역 테두리를 노란 선으로 보여 주고, 구역 밖은 빨간 미리보기와 안내 문구로 알린다.
- **여유 계산(측정이 아니라 기본값에서의 산수):** 구역 2,400 x 2,400 = 5.76 M cm², 집 20채 상한 = 1.8 M cm²로 구역의 약 31%다. 구역 밖은 약 17 M cm²이고 노드 50개가 점유하는 면적(최소 간격 150 cm 기준)은 그 5% 안팎이다.
- **치른 대가:** 노드가 중앙에서 최소 1,200 cm 떨어진다(시작 위치에서 걸어서 몇 초). 첫 채집까지의 이동이 늘었다. 건설 구역 밖에서는 지을 수 없다.
- 한계: 농사 밭 같은 새 점유물이 들어오면 구역 크기(1,200)를 다시 정해야 할 수 있다. 구역은 정사각형 하나로 고정이다.

**검증:** 서버 `play_resources_test`(노드가 구역 밖에만 놓임, 재생 200라운드 동안 한 번도 구역 안에 나타나지 않음, 구역을 끄면 중앙에도 놓임, 재시도 간격 20틱 정확히), `play_structures_test`(구역 경계 8방향 허용/거부, 구역을 끄면 맵 전체, 판정 순서), 서비스/통합(코드 18과 비용 미차감). Unreal `buildrules`(구역 경계, 순서)와 `build`(진짜 서버에서 구역 밖 자리는 클라이언트와 서버가 같은 결론). **변형 검증 10가지를 모두 잡았다**(구역 검사 제거, 왼쪽/오른쪽/위쪽 경계 비교, 구역 밖을 다른 코드로 응답, 노드 구역 규칙 끄기, 노드 반지름 누락, 재시도 간격, 재생 자리 구역 검사 제거, 처음 배치 구역 검사 제거). 서버 `ctest` 324개 모두 통과(MySQL 11개 건너뜀), Unreal `GameClientSpike` 모든 모드 통과(`buildrules` 29, `build` 39). **부하 재측정(완료 기준 9)을 했다**: 3회 모두 합격한 최대 방 수가 이전 500개에서 **450개**로 내려갔다(500개는 3회 모두 불합격, 누락 스냅샷 1.0~2.2%). 방당 서버 CPU가 약 15~27% 늘었고 원인(충돌, 속도 360, 재생 로직 중 무엇인지)은 가르지 못했다. 자세한 내용은 [results/stage4/game-load-recheck.md](../results/stage4/game-load-recheck.md).

## 조각 2~5 개요 (이후 상세 설계)

기획의 값과 규칙은 [game-plan.md](game-plan.md)가 기준이다. 각 조각은 구현 전에 이 문서에 상세 설계(범위, 기본값, 프로토콜, 완료 기준, 제외 범위)를 쓰고 확정한다.

- **2 하루와 잠:** 방마다 게임 시계(틱으로 센다, 06:00~02:00 = 12,000틱). 잠자기는 시작 집이나 완공된 집 앞에서만, 잠든 사람은 이동하지 않고 깨어날 수 있다. 방 안 모두가 잠들거나 02:00이 되면 **밤 정산**: 정해진 순서(완공 → 재생 → 이후 조각의 성장/판매 자리 → 저장 요청 → 다음 날 06:00, 모두 시작 위치)로 한 틱 안에 계산한다. 30초 재생과 5초 건설을 이 정산으로 옮긴다. 시계(날 번호, 틱)를 농장에 저장하고, 다시 열면 닫힌 시각부터 이어서 한다. 시작 집(고정, 이동을 막음)이 이 조각에서 생긴다.
- **3 아이템 일반화와 농사:** 일반 아이템 표(번호, 개수, 한 종류 최대 999)로 바꾸고 `wood`/`stone` 필드는 한동안 같이 채운다. 밭 칸(100 cm 격자, 농장 구역 안), 괭이/물뿌리개/심기/수확 행동(대상 칸, 거리 150 cm), 물 준 칸만 밤에 하루 성장, 정산 뒤 물 마름, 재수확 작물. 처음 만든 농장에 당근 씨앗 15개. 바뀐 칸만 방 전원에게 알린다. 밭과 아이템 저장.
- **4 경제:** 농장 공용 지갑(처음 500골드), 출하 상자(넣으면 인벤토리에서 빠지고 밤 정산 때 판매), 상점에서 씨앗 사기. 지갑과 출하 상자 내용 저장. 공동 목표는 열린 결정(기본값 없음).
- **5 제작과 도구 강화:** 도구 4종 x 3단계(개인, 상점에서 즉시 강화, 돈 + 석재), 강화 효과(칸 수, 한 번에 깎는 체력), 스프링클러 제작(밤 정산 때 4칸 물 주기, 1칸 장애물). 도구 단계와 스프링클러 저장.
