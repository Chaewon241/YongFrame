# 콘텐츠 조각 2.5: 맵 여러 개 (설계)

> 상태: **구현 전 설계.** 조각 2(하루와 잠, [content-day.md](content-day.md))의 서버 S0-1·S0-2가 끝난 코드 기준으로 썼다. 구현은 **조각 2가 끝난 뒤**(S0-3~S0-6과 Unreal까지, 적어도 서버 S0 전체) 시작한다. 구현 세션은 이 문서와 CLAUDE.md만 읽고 시작할 수 있게 썼다. 기획은 [game-plan.md](game-plan.md) "맵", 조각 순서는 [content-roadmap.md](content-roadmap.md). "사용자 결정"이 아닌 값은 **임의 기본값**이고 `PlayConfig`에서 바꾼다. 측정 합격 기준(완료 기준 13)은 측정 전에 쓴 것이다. 구현 결과는 맨 아래 절에 이어서 적는다.

## 1. 목표

한 방(농장)을 **맵 여러 개**로 나눈다. 플레이어는 맵 가장자리의 출입구로 걸어가 이웃 맵으로 넘어가고, 4명이 서로 다른 맵에 흩어져 일할 수 있다. 서버는 **같은 맵에 있는 사람에게만** 그 맵의 위치와 변화를 보낸다(맵 단위의 가장 단순한 관심 영역 관리).

이 조각이 끝나면:

- 농장 맵(시작 집, 지은 집)이 가운데에 있고, 서쪽은 숲(나무 30), 동쪽은 채석장(돌 20)이다
- 지금의 "구역 분리"(건설 구역/자원 구역)를 **맵 분리**가 대신한다
- 밤 정산은 모든 맵에서 돌고, 아침에는 모두 농장 맵의 시작 집 앞에서 깬다

## 2. 사용자 결정

| 항목 | 결정 |
| --- | --- |
| 맵 방식 | **작은 맵 여러 개를 출입구로 잇는다.** 큰 맵 하나의 재생 없는 탐험은 하지 않는다 |
| 기존 결정(유지) | 하루 10분, 모두 자면 넘어감, 밤에만 재생과 완공, 돈 공용/아이템 개인, 잠은 시작 집이나 완공된 집 앞 |

## 3. 조각 2 구현에서 이어받는 사실 (바꾸지 않는다)

조각 2 서버(S0-1·S0-2)가 이미 정한 것이다. 이 조각은 이것을 **맵마다로 넓힐 뿐 뜻을 바꾸지 않는다.**

| 사실 | 이 조각에서 |
| --- | --- |
| 노드 재생은 **밤 정산에서만**(`RespawnAllDepleted`), 자리를 못 찾은 노드만 `respawn_retry_ticks`로 재시도 | 맵마다 같은 규칙. 숲과 채석장 맵에서 돈다 |
| 집 완공은 **밤 정산에서만**(`CompleteAll`), 건설 중 `ready_tick = 0` | 집은 농장 맵에만 있으므로 농장 맵에서만 돈다 |
| 시작 집 `Landmark`: (2500, 2850), 400 x 300, 이동을 막고 그 위에 지을 수 없음, 시작 칸에서 북쪽 두 칸이 100 cm 거리 | **농장 맵의 고정 물체**로 그대로 둔다. 좌표는 농장 맵 좌표다 |
| 메시지 ID 116~119(`SleepRequest/Response`, `SleepUpdate`, `DayStarted`), 120~125(계정) 사용 중 | 새 메시지는 **126부터**. 109는 비어 있지만 순서를 어지럽히지 않으려고 쓰지 않는다 |
| 결과 코드 0~22 사용 중(21 `GAME_SLEEP_TOO_FAR`, 22 `GAME_SLEEPING`) | **새 결과 코드를 만들지 않는다.** 기존 코드의 뜻을 맵으로 넓힌다(6절) |
| `RoomState` 필드 1~9 사용 중(7 시계, 8 고정 물체, 9 잠든 사람) | 새 필드는 10부터 |
| 방의 시간은 `World::tick()` 하나(시계 `day_start_tick`, 채집 쿨다운, 재시도 예약이 이 틱을 쓴다) | 맵이 여러 개여도 **방 틱은 하나**여야 한다(5.1) |
| 통계 줄 `하루{...}` 묶음, `틱시간{이동= 갱신= 구성= 전송= 합=}` 모양은 집계 스크립트가 정규식으로 읽는다 | 새 통계는 **별도 묶음**으로 둔다(8절) |

## 4. 범위

**포함**

- 방 안의 맵 목록(농장, 숲, 채석장)과 맵마다의 월드(이동, 충돌), 노드, 구조물, 고정 물체
- 출입구 판정과 맵 이동(서버 판정), 도착 위치
- 맵별 수신자: 스냅샷, 노드 변화, 구조물 변화는 같은 맵 사람에게만
- 맵에 들어갈 때 그 맵의 전체 상태 보내기, 누가 어느 맵에 있는지 방 전원에게 알리기
- 행동 판정의 맵 규칙(다른 맵의 노드, 숲에서 건설, 숲에서 잠)
- 밤 정산을 맵마다, 아침에 모두 농장 맵으로
- 옛 구성(맵 하나 + 구역 분리)을 설정으로 남김(부하 비교와 일부 기존 시험용)
- `game_client`, `game_load_client`의 맵 대응, 맵 이동이 섞인 부하 측정
- Unreal: 맵 표현, 넘어갈 때의 전환, 다른 사람이 있는 맵 표시

**제외**

- 마을 맵과 상점(조각 4), 광산 맵(나중 후보)
- 맵마다 다른 크기, 맵 안의 지형(물, 언덕, 길), 문을 열고 들어가는 실내 맵
- 맵을 넘는 원거리 상호작용(다른 맵 사람과 교환 등), 맵 사이 채팅 구분(채팅은 지금처럼 방 단위)
- 미니맵, 지도 화면
- 맵 단위의 저장 구조 변경(저장은 지금처럼 농장 맵의 구조물만, 7절)
- 성능 최적화(측정은 하되 이 조각에서 최적화하지 않는다)

## 5. 규칙

### 5.1 방과 맵

- 방 하나는 맵 목록을 가진다. 맵은 번호(`map_id`)로 구분한다.

| map_id | 종류 | 들어가는 것 | 이웃 |
| ---: | --- | --- | --- |
| 0 | 농장(`MAP_FARM`) | 시작 집, 지은 집. 노드 없음 | 서쪽 → 숲, 동쪽 → 채석장 |
| 1 | 숲(`MAP_FOREST`) | 나무 30 | 동쪽 → 농장 |
| 2 | 채석장(`MAP_QUARRY`) | 돌 20 | 서쪽 → 농장 |

- 맵마다 5,000 x 5,000 cm, 좌표는 **맵마다 따로**(원점은 그 맵의 모서리)다. 지금의 이동 속도, 반지름, 충돌 규칙을 그대로 쓴다.
- **방 틱은 하나다.** 모든 맵은 같은 틱 번호로 움직인다(사람이 없는 맵도 틱은 센다). 스냅샷의 `tick`, `DayClock.day_start_tick`, 채집 쿨다운(`last_gather_tick`), 재생 재시도 예약이 모두 이 하나의 틱을 쓴다. 그래서 맵을 넘어도 쿨다운과 시계가 어긋나지 않는다. 틱을 `World`에서 `Room`으로 옮기든, 모든 맵의 `World`를 같이 돌리든 방법은 구현이 정한다. 단 **"모든 맵의 틱이 같다"를 시험한다.**
- 노드 번호는 **방 안에서 하나로 이어진다**(숲 1~30, 채석장 31~50). 그래서 `GatherRequest{node_id}`는 바뀌지 않는다. 구조물 번호도 지금처럼 방 안에서 이어진다(구조물은 농장 맵에만 있다).
- 노드 배치 시드는 맵마다 다르다(`layout_seed`와 `map_id`로 정한다). 같은 설정이면 모든 방이 같은 배치다(지금과 같은 결정성).

### 5.2 출입구와 맵 이동

| 항목 | 기본값 | 비고 |
| --- | --- | --- |
| 출입구 위치 | 이웃과 맞닿은 가장자리의 **가운데**, 폭 400 cm (가장자리 방향으로 2,300~2,700) | 농장 서쪽(x = 0) ↔ 숲 동쪽(x = 5,000), 농장 동쪽(x = 5,000) ↔ 채석장 서쪽(x = 0) |
| 넘어가는 조건 | 이동 계산 뒤 몸 중심이 출입구 가장자리에서 **50 cm 이하**(경계 포함)이고 가장자리 방향 좌표가 출입구 폭 안(경계 포함) | 몸 반지름이 40 cm라 맵 경계에 붙으면 중심이 40 cm가 되므로 닿을 수 있다 |
| 도착 위치 | 이웃 맵의 맞은편 출입구에서 **150 cm 안쪽**, 가장자리 방향 좌표는 그대로(출입구 폭 안으로 자른다) | 150 > 50이라 도착하자마자 되돌아가지 않는다 |
| 도착 자리가 막힘 | 지금 `AddPlayer`의 "가장 가까운 빈 자리" 규칙 | 출입구 앞은 비워 두므로(5.3) 보통 막히지 않는다 |
| 이동 방향 | **유지한다**(넘어간 뒤에도 같은 방향으로 계속 걷는다). `last_input_seq`도 그대로 | |
| 한 틱에 넘어가는 횟수 | 많아야 한 번 | |
| 잠든 사람 | 움직이지 않으므로 넘어가지 않는다 | |

- 넘어가는 판정은 **틱마다, 맵마다 이동 계산 뒤, 밤 정산 판정 전에** 한다(틱 순서는 5.5).
- 넘어간 사람은 옛 맵의 월드에서 빠지고 새 맵의 월드에 들어간다. 다른 사람과는 지금처럼 충돌하지 않는다.

### 5.3 맵별 행동 규칙

| 행동 | 규칙 | 결과 코드 |
| --- | --- | --- |
| 채집 | 내가 있는 맵의 노드만. 다른 맵의 노드 번호는 **없는 노드**로 본다 | `GAME_NODE_NOT_FOUND`(9) |
| 건설 | **농장 맵에서만.** 농장 맵은 맵 전체가 건설 가능(발자국 전체가 맵 안). 숲과 채석장에서 지으면 | `GAME_BUILD_OUT_OF_ZONE`(18)의 뜻을 "건설할 수 없는 곳(구역 밖 또는 건설할 수 없는 맵)"으로 넓힌다 |
| 건설, 출입구 앞 | 발자국이 **출입구 앞 300 cm**(출입구 폭 x 가장자리에서 300 cm인 직사각형)와 겹치면 | `GAME_BUILD_BLOCKED`(14) |
| 잠 | 농장 맵의 시작 집이나 완공된 집 앞만(지금 규칙). 다른 맵에는 잘 곳이 없다 | `GAME_SLEEP_TOO_FAR`(21) |
| 노드 배치와 재생 | 그 맵의 출입구 앞 300 cm와 도착 위치 둘레(반지름 200 cm)를 피한다. 숲과 채석장은 **구역 제한이 없다**(맵 전체, 가장자리 여백 200 cm) | |

판정 순서는 바뀌지 않는다. "다른 맵의 노드"는 노드 없음과 같은 자리이고, "건설할 수 없는 맵"은 구역 밖과 같은 자리다.

- 채집: 방에 없음 → 잠듦 → **노드 없음(다른 맵 포함)** → 고갈 → 너무 멂 → 쿨다운
- 건설: 방에 없음 → 잠듦 → 종류 → 상한 → 너무 멂 → **구역 밖(건설할 수 없는 맵 포함)** → 겹침/맵 밖(출입구 앞 포함) → 자원 부족

### 5.4 밤 정산 (맵마다)

조각 2의 순서(content-day.md 5.4)를 그대로 두고 대상만 넓힌다.

1. 완공: 농장 맵의 건설 중인 집 전부
2. (조각 3~5 자리) 그대로
3. 깨우기와 아침 위치: 모두 깨우고, **어느 맵에 있었든 농장 맵**의 자기 칸 시작 위치로 옮긴다. 맵이 바뀐 사람은 5.6의 "맵 들어감"을 받는다
4. 재생: **모든 맵**의 고갈된 노드 전부. 맵 번호 순서(0, 1, 2)로 돌려 결정성을 지킨다. 3에서 모두 농장 맵으로 옮겼으므로 숲과 채석장의 재생 자리는 플레이어 몸을 피할 일이 없다
5. 날 넘김: 그대로

### 5.5 틱 순서

방마다, 한 틱에:

1. 이동 계산: 모든 맵(사람이 있는 맵만 실제 계산해도 된다. 틱 번호는 모든 맵이 같다)
2. **맵 이동 판정**(5.2): 사람 번호 순서로
3. 밤 정산 판정과 정산(5.4)
4. 낮 재생 재시도: 모든 맵
5. 보낼 것 확보: **맵마다** 그 맵에 있는 사람이 수신자다
6. 전송

### 5.6 알림 (같은 맵 사람에게만)

| 알림 | 받는 사람 |
| --- | --- |
| `WorldSnapshot` | **그 맵에 있는 사람**, 그 맵에 있는 사람의 위치만 |
| `ResourceUpdate`, `StructureUpdate` | 그 맵에 있는 사람 |
| `MapEntered`(새 메시지, 6절) | 맵을 넘어간 **본인**에게, 들어간 맵의 전체 상태 |
| `RoomEvent{kind = MAP_CHANGED}` | **방 전원**(본인 포함). 누가 어느 맵으로 갔는지 |
| `DayStarted`, `SleepUpdate`, `RoomEvent`(입장, 퇴장, 방장) | 지금처럼 방 전원 |
| 채집/건설/잠 응답 | 지금처럼 요청한 사람 |

한 사람이 받는 순서:

- 맵을 넘어간 틱: `MapEntered` → (지금 순서대로) `WorldSnapshot`(새 맵) → `ResourceUpdate` → `StructureUpdate`. 그 앞에 방 전원 알림인 `RoomEvent{MAP_CHANGED}`가 온다
- 밤 정산 틱: `DayStarted` → (맵이 바뀌었다면) `MapEntered`(농장) → 나머지는 지금 순서

**같은 틱의 변화와 맵 이동:** 맵을 넘어간 틱에 옛 맵에서 생긴 변화(예: 같은 틱에 다른 사람이 숲의 나무를 침)는 그 사람에게 보내지 않는다. 새 맵의 상태는 `MapEntered`가 그 틱 끝의 값으로 담는다. 다시 옛 맵에 들어가면 그때의 `MapEntered`가 최신 상태를 준다. 그래서 놓치는 변화가 없다.

**늦게 들어온 사람:** 입장하면 농장 맵의 시작 칸에 선다(지금처럼). `RoomState`에는 **농장 맵의 상태만** 담는다(6절). 다른 사람이 어느 맵에 있는지는 `RoomState.players[].map_id`로 안다.

## 6. 프로토콜 (`proto/game.proto`, 하위 호환으로 더한다)

| ID | 메시지 | 방향 | 설명 |
| ---: | --- | --- | --- |
| 126 | `MapEntered{uint64 tick, MapState map, float x, float y}` | S→C | 내가 맵에 들어갔다. 들어간 맵의 전체 상태와 내 도착 위치 |

```proto
enum MapKind {
  MAP_FARM = 0;
  MAP_FOREST = 1;
  MAP_QUARRY = 2;   // 마을(조각 4), 광산(나중)은 그때 더한다
}

message MapExit {
  uint32 to_map_id = 1;
  float x = 2;       // 출입구 가운데(가장자리 위의 점), 이 맵 좌표
  float y = 3;
  float width = 4;   // 출입구 폭(가장자리 방향)
}

// 맵 하나의 정적인 정보.
message MapInfo {
  uint32 map_id = 1;
  MapKind kind = 2;
  float width = 3;
  float height = 4;
  repeated MapExit exits = 5;
}

// 맵 하나의 지금 상태. 맵에 들어갈 때, 방에 들어갈 때(농장 맵) 보낸다.
message MapState {
  uint32 map_id = 1;
  repeated ResourceNode nodes = 2;
  repeated Structure structures = 3;
  repeated Landmark landmarks = 4;
}
```

기존 메시지에 더하는 것:

- `RoomState.map_id = 10`: 지금 내가 있는 맵(입장 직후에는 항상 농장 맵 0)
- `RoomState.maps = 11`: `repeated MapInfo`, 방의 모든 맵(정적인 정보)
- **`RoomState.nodes`(5), `structures`(6), `landmarks`(8)의 뜻이 바뀐다:** 방 전체가 아니라 **`map_id` 맵의 것만** 담는다. 농장 맵에는 노드가 없으므로 입장 응답의 `nodes`는 비어 있다. 필드 번호와 형은 그대로다
- `PlayerInfo.map_id = 3`: 그 사람이 지금 있는 맵
- `RoomEvent.Kind`에 `MAP_CHANGED = 3`, `RoomEvent.map_id = 4`(들어간 맵)
- `WorldSnapshot.map_id = 3`: 이 스냅샷이 어느 맵의 것인지. 클라이언트는 지금 맵이 아닌 스냅샷을 버린다(순서는 서버가 지키지만 방어용)
- `ResourceUpdate.map_id = 3`, `StructureUpdate.map_id = 3`: 같은 이유

**호환성:** 메시지와 필드 추가만 있다. 다만 `RoomState.nodes`의 뜻이 바뀌므로, **맵을 모르는 지금의 Unreal 클라이언트는 입장해도 나무와 돌을 보지 못한다**(농장 맵에는 노드가 없다). 서버와 Unreal을 함께 올려야 한다. 이 변경은 [stage4.md](stage4.md) 프로토콜 표와 [unreal-client.md](unreal-client.md)에 기록한다.

## 7. 저장

- **스키마를 바꾸지 않는다.** 저장하는 구조물은 지금처럼 농장 맵의 집뿐이고 좌표는 농장 맵 좌표다. 옛 농장의 집 좌표(지금의 건설 구역, 중앙 사방 1,200 cm 안)는 농장 맵 좌표로 그대로 맞는다. 출입구 앞(가장자리 300 cm)과도 겹치지 않는다.
- 사람이 있던 맵은 저장하지 않는다. 농장을 다시 열거나 다시 들어오면 농장 맵의 시작 칸에서 시작한다.
- 숲과 채석장의 노드는 지금처럼 저장하지 않는다(밤마다 다시 생긴다).
- 시계(조각 2 S0-3의 `farm_clock`)는 영향이 없다.
- 이후 다른 맵에 구조물이 생기면(예: 광산 입구) 그때 `farm_structures`에 `map_id` 열을 더한다(새 마이그레이션). 이번에는 더하지 않는다.

**`kSingle`을 남기는 이유:** 지금까지의 부하 결과(results/stage4)는 맵 하나 구성이다. 같은 세션에서 옛 구성과 새 구성을 번갈아 재려면 옛 구성이 필요하다. 또 노드가 시작 위치 근처에 있어야 하는 기존 채집/충돌 시험 중 맵과 무관한 것은 `kSingle`로 돌려도 된다. **새 기본값은 `kFarmForestQuarry`다.** 시험을 `kSingle`로 돌린 경우 이름과 이유를 구현 결과 절에 적는다.

**기존 시험에 생기는 변화(예상):** 입장 응답의 노드 목록을 보는 시험(농장 맵에는 노드가 없다), 시작 위치 근처의 노드를 치는 채집 시험, 건설 구역 경계 시험(농장 맵은 구역 제한이 없다), 스냅샷 인원을 보는 시험. 규칙이 바뀐 시험은 같은 성질을 새 규칙으로 다시 시험한다.

## 9. 완료 기준 (구현 전에 확정)

**서버**

1. **구성:** 기본 구성은 맵 3개(농장 0, 숲 1, 채석장 2)다. 노드는 숲에 나무 30, 채석장에 돌 20이고 농장에는 없다. 노드 번호는 1~50으로 이어진다. 시작 집은 농장 맵에만 있다. 같은 설정이면 같은 배치다(결정성). `kSingle`은 지금과 똑같이 동작한다(기존 시험의 결과가 같다).
2. **방 틱 하나:** 사람이 어느 맵에 있든 모든 맵의 틱 번호가 같다. 숲에서 채집하고 바로 농장으로 넘어갔다 돌아와 다시 쳐도 쿨다운이 정확하다. 시계는 맵과 상관없이 흐른다.
3. **넘어가는 판정:** 출입구로 걸어가면 넘어간다. 경계를 포함한다(가장자리 50.0 cm는 넘어가고 50.1 cm는 아님, 출입구 폭 끝 2,300.0과 2,700.0은 넘어가고 바깥은 아님). 출입구가 아닌 가장자리는 막혀 있다(지금의 맵 경계). 잠든 사람은 넘어가지 않는다. 한 틱에 한 번만 넘어간다.
4. **도착:** 이웃 맵의 맞은편 출입구 150 cm 안쪽, 가장자리 방향 좌표 유지, 이동 방향과 `last_input_seq` 유지. 도착하자마자 되돌아가지 않는다. 같은 방향을 계속 누르면 맵 안으로 걸어 들어간다. 도착 자리가 막혀 있으면 가장 가까운 빈 자리다.
5. **맵별 수신:** 스냅샷은 같은 맵 사람만 받고 같은 맵 사람의 위치만 담는다. 노드 변화(숲의 채집)는 숲에 있는 사람만, 구조물 변화(농장의 건설)는 농장에 있는 사람만 받는다. `MAP_CHANGED`는 방 전원이 받는다. 다른 방에는 영향이 없다.
6. **맵 상태:** 맵에 들어가면 `MapEntered`가 그 맵의 노드(현재 체력), 구조물, 고정 물체, 내 도착 위치를 담는다. 숲을 떠난 사이 다른 사람이 나무를 베었으면 돌아왔을 때 그 값이 맞다. 늦게 들어온 사람의 `RoomState`는 농장 맵 상태, 모든 맵의 정보, 모든 사람의 맵을 담는다.
7. **알림 순서:** 맵을 넘어간 틱에 그 사람은 `MapEntered`를 새 맵의 스냅샷보다 먼저 받는다. 밤 정산 틱에는 `DayStarted` → `MapEntered` → 스냅샷 순서다.
8. **행동 규칙:** 다른 맵의 노드 번호로 채집하면 `GAME_NODE_NOT_FOUND`이고 상태가 바뀌지 않는다. 숲과 채석장에서 건설하면 `GAME_BUILD_OUT_OF_ZONE`이다. 농장 맵은 맵 전체에 지을 수 있지만 출입구 앞 300 cm와 겹치면 `GAME_BUILD_BLOCKED`다(경계 포함: 닿기만 하면 허용). 숲에서 자면 `GAME_SLEEP_TOO_FAR`다. 노드는 출입구 앞과 도착 둘레에 놓이지 않고 재생하지도 않는다.
9. **밤 정산:** 숲과 채석장에 흩어져 있어도 모두 잠들면(잘 곳은 농장 맵뿐이므로, 실제로는 모두 농장에 와서 잠들거나 02:00 강제) 정산하고, 모두 농장 맵의 시작 칸에서 깬다. 맵이 바뀐 사람은 `MapEntered`(농장)를 받는다. 모든 맵의 고갈된 노드가 되살아난다. 같은 상태면 같은 결과다(결정성).
10. **저장:** 스키마 변경이 없다. 옛 농장(맵 하나 시절의 집)을 열면 집이 농장 맵에 같은 좌표로 있다. 다시 들어오면 농장 맵 시작 칸이다. 기존 농장 시험이 통과한다.
11. **견고함:** 넘어가는 틱에 연결 끊김, 넘어가는 틱에 방 나가기, 같은 틱에 여러 명이 넘어감, 넘어가는 틱에 밤 정산, 맵을 넘는 순간의 채집/건설 요청, 비정상 좌표(NaN 입력은 지금 규칙으로 막힘)에서 죽지 않는다.
12. **기존 기능 유지:** 기존 `ctest`가 통과한다. 8절의 변화로 고친 시험과 `kSingle`로 돌린 시험은 목록과 이유를 남긴다.
13. **부하 측정 (측정 전에 확정):**
    - 질문: 맵을 나누면 같은 방 수에서 서버 비용이 달라지는가. 맵 이동이 섞이면 틱이 밀리는가.
    - 조건: Release, `--io-threads 0`, 방 400개, 생성기 설정은 [stage4.md](stage4.md) 게임 부하 측정과 같다. **A** = `kSingle`(옛 구성), **B** = 기본 구성, 모든 플레이어가 농장 맵에 머문다, **C** = 기본 구성, `--map-hop`(플레이어마다 약 10초에 한 번 이웃 맵으로 넘어갔다 돌아오는 워크로드, 생성기가 출입구로 걷게 한다). 같은 세션에서 A, B, C를 번갈아 3회씩, 매 실행 새 서버, 실행 전 PC 상태 기록.
    - 합격 기준: [stage4.md](stage4.md) 표 그대로(스냅샷 도착 간격 p99 100 ms 이하, 입력 반영 지연 p99 100 ms 이하, 누락 1% 이하, 틱 건너뜀 0.1% 이하, 정합성 위반 0, 생성기 포화 아님). B와 C가 이 기준을 만족해야 "맵을 나눠도 방 400개가 합격한다"고 쓴다.
    - 함께 기록: 서버 CPU(방당), 틱 시간 분해, 맵 이동 수, 클라이언트가 받은 스냅샷 대역폭. C에서는 맵마다 수신자가 줄어 스냅샷이 작아질 수 있으나 **측정 전에는 주장하지 않는다.**
    - 불합격이어도 그대로 적고 이 조각에서는 최적화하지 않는다. 측정하고 기록하면 이 기준은 충족이다. 결과는 `results/stage4/maps.md`와 원본.
14. **변형 검증:** 최소 목록: 넘어가는 거리 `<=`를 `<`로, 출입구 폭 경계, 도착 거리를 50 이하로(되돌아감), 방향을 유지하지 않음, 잠든 사람도 넘어감, 맵별 수신자를 방 전원으로, 스냅샷에 다른 맵 사람 포함, 노드 변화를 방 전원에게, `MapEntered` 누락, `MapEntered`를 스냅샷 뒤에, `MAP_CHANGED`를 본인에게만, 다른 맵 노드 채집 허용, 숲에서 건설 허용, 출입구 앞 건설 허용, 노드가 출입구 앞에 놓임, 밤 정산에서 농장 맵으로 옮기지 않음, 밤 정산에서 숲 노드를 재생하지 않음, 맵마다 틱이 따로 흐름, 늦은 입장자의 맵 정보 누락. 살아남은 변형은 시험을 보강하거나 동등 변형인 근거를 적는다.
15. **문서:** 구현 결과 절, [stage4.md](stage4.md) 프로토콜 표(126, 새 필드, `RoomState.nodes`의 뜻 변경, 결과 코드 9/18/21의 뜻 확장), [unreal-client.md](unreal-client.md) 기준 바이트, [content-roadmap.md](content-roadmap.md)의 구역 분리 절(맵 분리로 대체됨), CLAUDE.md 명령(`/map`, `--map-hop`)과 코드 구조.

**Unreal**

16. **자동 시험(`GameClientSpike`, 진짜 서버):** 농장 서쪽 출입구로 걸어가면 숲으로 넘어가 `MapEntered`를 받고 나무 목록이 생긴다. 숲에서 나무를 치고 농장으로 돌아왔다가 다시 숲에 가면 체력이 맞다. 두 사람이 다른 맵에 있으면 서로의 스냅샷 위치를 받지 않고 `MAP_CHANGED`로 맵만 안다. 숲에서 건설하면 거부된다. 밤 정산 뒤 농장 맵에서 깬다. 순수 함수 모드: 출입구 판정 경계, 도착 위치, 맵 오프셋 변환.
17. **PIE(사람이 확인):** 창 2개. 한 사람이 서쪽으로 걸어가면 화면이 전환되어 숲에 서고, 다른 사람 화면에서는 그 사람이 사라지고 HUD에 "숲에 있음"이 보인다. 숲에서 나무를 베어 돌아오고, 둘 다 농장에서 자면 다음 날 농장에서 깬다.

## 11. 위험

- **입장 응답의 뜻 변경:** `RoomState.nodes`가 농장 맵 것만 담게 되면 옛 클라이언트에서 나무가 사라진다. 서버와 Unreal을 함께 올려야 한다(6절).
- **방 틱 하나:** 지금 시간은 `World::tick()`에 묶여 있고 시계, 쿨다운, 재시도가 그것을 쓴다. 맵마다 `World`가 생기면 틱이 갈라질 수 있다. 완료 기준 2가 이것을 막는다.
- **부하 생성기의 정합성 검사:** 지금 생성기는 "스냅샷에 4명"을 검사한다. 맵이 갈리면 이 검사가 틀린다. 생성기를 먼저 고쳐야 측정이 의미 있다.
- **이동 거리 늘어남:** 노드가 이웃 맵에만 있어 첫 채집까지 걷는 거리가 늘어난다(시작 칸에서 서쪽 출입구까지 약 2,400 cm, 약 7초). 구역 분리 때보다 길다. 의도된 변화이고 값은 설정이다.
- **4명이 흩어지는 협동:** 다른 사람이 보이지 않는 시간이 생긴다. HUD의 "누가 어느 맵" 표시로 보완한다.

## 12. 조각 2 세션에 전할 것 (조각 2의 범위는 바꾸지 않는다)

조각 2의 구현과 [content-day.md](content-day.md) 13절은 그 세션 담당이라 이 문서에서 고치지 않았다. 조각 2.5가 쉬워지도록 **남은 S0-3~S0-6에서 해 두면 좋은 것**(필수 아님)만 적는다.

- **`game_load_client`(S0-4, 반영됨):** 조각 2 S0-4가 "`DayStarted`를 받으면 그 연결의 다음 스냅샷 한 번은 이동 거리 검사를 건너뛴다"로 구현했다(content-day.md 13절). 조각 2.5는 같은 장치를 `MapEntered`에도 걸면 된다. 원래 제안: `DayStarted` 직후 이동 거리 검사를 건너뛰는 처리를 "순간이동 알림 뒤 한 번 건너뛰기"라는 일반 장치로 만들어 두면 조각 2.5의 `MapEntered`에 그대로 쓸 수 있다. 스냅샷 인원 검사(`players_per_room`)는 조각 2.5에서 바뀐다.
- **`RunNight`의 깨우기(3단계):** "칸 번호 → 시작 위치"를 바로 쓰지 않고 "이 사람을 (맵, 좌표)에 놓기" 함수를 거치게 해 두면 조각 2.5에서 "농장 맵으로 옮기기"만 더하면 된다.
- **틱:** 새 코드에서 `world().tick()`을 직접 늘려 쓰기보다 방 틱을 돌려주는 함수 하나(예: `Room::tick()`)를 거치면 조각 2.5에서 틱을 옮기기 쉽다.
