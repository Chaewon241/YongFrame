# 검증 및 성능 실험 계획

이 문서는 측정 전에 무엇을 고정하고 무엇을 바꿀지 정하는 기록 양식이다. 수치가 나오기 전에는 “최대 몇 명” 또는 “몇 % 향상”을 목표나 결과처럼 적지 않는다.

## 1. 기능 검증부터

1단계에서는 [패킷 계약](protocol.md)의 정상·분할·합쳐진 프레임·비정상 입력을 확인한다. 2단계에서는 다중 사용자 채팅, 기록 저장·조회, DB 장애·복구를 추가한다. 성능 결과는 해당 기능 검증이 통과한 빌드에서만 채택한다.

1단계부터 현재/최대 연결 수, 수신·송신 프레임 수, 파싱/네트워크 오류 수, 연결별 송신 큐 크기를 확인할 수 있게 한다. 수집 비용이 부하 측정에 영향을 주지 않도록 부하 실험에서는 상세 패킷 로그를 끄고 계측 설정을 결과와 함께 기록한다.

## 2. 수용 인원 정의

**최대 안정 연결 수**는 특정 워크로드를 정해진 측정 시간 동안 수행하면서 다음 조건을 모두 만족하는 가장 큰 동시 연결 수로 정의한다. 임계값은 첫 기준 측정 전에 정하고 결과를 본 뒤 바꾸지 않는다.

- 연결 성공률과 끊김/오류율의 허용 범위
- 왕복 지연 p95·p99의 허용 상한
- 유효 응답 비율과 처리량
- 메모리 사용량이 지속적으로 증가하지 않는지
- CPU, 네트워크, 파일 디스크립터/핸들, DB 연결 등 자원 한도

**서로 다른 두 워크로드를 별도로 보고한다.**

| 워크로드 | 무엇을 확인하나 | 예시 |
| --- | --- | --- |
| Idle 연결 | 접속 유지 비용과 자원 한도 | 연결 후 주기적인 작은 Ping만 전송 |
| Active 연결 | 실제 메시지 처리 능력 | 모든 연결이 정해진 초당 메시지 수·payload 크기로 Ping 또는 채팅 전송 |

숫자 예시는 측정 설정의 출발점일 뿐이며, 합격 기준은 실제 실험 전에 기록한다. 채팅 단계에서는 같은 방의 수신자 수에 따라 전파 비용이 달라지므로 방 크기 분포도 명시한다.

## 3. 공통 측정 절차

1. 동일한 커밋·빌드 설정으로 측정한다. OS, CPU, RAM, 네트워크, Boost/Protobuf/MySQL 버전, 서버 설정, 부하 생성기 사양을 기록한다.
2. 서버와 부하 생성기는 가능하면 다른 머신에서 실행한다. 로컬 테스트라면 그 한계를 명시한다.
3. 연결 수를 단계적으로 올린다. 각 단계에서 예열, 안정 구간, 종료 구간을 구분하고 동일한 시간을 사용한다.
4. 각 조건을 여러 차례 반복하고 중앙값과 분산을 기록한다. 오류가 있는 반복도 숨기지 않는다.
5. 클라이언트의 실제 송신 수와 수신 수를 대조한다. 부하 생성기의 CPU/네트워크/포트 한도도 살핀다.
6. 평균 지연만으로 판단하지 않고 p50/p95/p99를 남긴다. 처리량과 성공률을 함께 표시한다.
7. Windows와 Linux는 각각 결과를 내고, OS 설정 차이를 명시한다. 플랫폼 간 숫자를 조건 없이 합치지 않는다.

## 4. 비교 실험 후보

병목을 관찰한 후 우선순위를 정한다. **한 번에 한 변수만** 바꾸고 기준 버전으로 되돌려 재측정한다.

| 관찰된 현상 | 비교할 후보 | 함께 볼 비용 |
| --- | --- | --- |
| CPU 사용이 높고 할당 횟수가 많음 | 기본 할당기와 버퍼/객체 풀 | 메모리 점유, 복잡도, 누수 위험 |
| 송신 호출이 잦고 작은 패킷이 많음 | 즉시 송신과 제한된 배치 송신 | 지연 증가, 큐 적체 |
| I/O 처리량이 정체 | `io_context` 실행 스레드 수 | 경쟁·컨텍스트 전환·순서 보장 |
| 느린 수신자로 메모리가 증가 | 무제한 큐와 제한 큐·연결 종료 정책 | 메시지 손실/강제 종료 |
| 채팅 DB 응답이 지연 | DB 연결 수, 쓰기 경로, 인덱스 | DB CPU·락·쓰기 지연 |

MemoryPool은 **후보 중 하나**다. 할당이 병목이라는 증거가 없으면 구현하지 않는다. 비교 결과가 비슷하거나 다른 비용이 더 크면 단순한 방식을 유지한다.

## 5. 실험 기록 템플릿

새 실험마다 `results/YYYY-MM-DD-주제.md`와 원본 결과 파일을 함께 남긴다.

```md
# 실험 제목

- 질문/가설:
- 커밋과 빌드 설정:
- 서버/부하 생성기 환경:
- 워크로드: 연결 수, 메시지 빈도·크기, 방 크기, 측정 시간
- 고정한 변수:
- 바꾼 변수(A/B):
- 합격 기준(측정 전 작성):
- 반복별 원본 결과 위치:
- 결과: 성공률, 처리량, p50/p95/p99, CPU, 메모리, 오류/끊김
- 해석과 한계:
- 결정: 채택 / 보류 / 기각, 이유
```

프로젝트 소개에 올릴 그래프는 이 기록과 원본 측정값을 통해 다시 만들 수 있어야 한다.
