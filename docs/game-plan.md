# 게임 기획 (4단계 이후)

> 상태: **스타듀밸리 풍으로 다시 짠 기획.** 1~4인 협동 농장이라는 큰 방향은 그대로이고, 게임의 기본 단위를 **"하루"**로 바꿨다. "사용자가 정한 것"은 사용자의 결정이고, "기본값"은 내가 임의로 정한 값이라 바꿀 수 있다(값은 서버 `PlayConfig` 한 곳에서 바꾼다). 조각별 순서, 상세 설계, 합격 기준은 [content-roadmap.md](content-roadmap.md)에 있고, 각 조각은 구현 전에 그 문서에서 확정한다.

## 한 줄 요약

1~4명이 한 농장에서 함께 **하루하루** 밭을 갈고, 작물을 키워 출하하고, 번 돈으로 씨앗을 사고 도구를 강화하는 협동 농장 게임. 3D 탑뷰. 클라이언트는 Unreal, 서버는 이 저장소의 C++ 서버이며 **서버가 시간, 판정, 정산을 소유한다.**

## 참고 범위 (지킬 것)

스타듀밸리에서 가져오는 것은 **장르와 규칙의 모양**(하루 루프, 밭 갈기와 물 주기, 출하 상자, 밤 정산, 도구 강화)뿐이다. 스타듀밸리의 이름, 캐릭터, 마을과 맵 구성, 작물과 아이템 이름, 그림, 음악은 쓰지 않는다. 작물, 아이템, 장소 이름은 이 프로젝트에서 따로 정한다(아래 기본값의 이름은 흔한 작물 이름이다).

## 하루 루프 (게임의 중심)

```
아침 6시 ─▶ 일하기(밭 갈기, 심기, 물 주기, 수확, 채집, 출하, 구매, 제작) ─▶ 잠자기 ─▶ 밤 정산 ─▶ 다음 날 아침 6시
                                                                            │
     작물 성장(물 준 칸만), 물 마름, 출하 판매 → 농장 공용 돈, 나무/돌 재생, 집 완공, 저장
```

- 하루는 **실시간 약 10분**이다(사용자 결정). 게임 시계는 아침 6시에 시작해 새벽 2시에 끝난다(게임 시간 20시간 = 실시간 10분, 게임 1시간 = 실시간 30초).
- **방 안의 모든 사람이 잠들면** 밤 정산을 하고 다음 날로 넘어간다(사용자 결정). 새벽 2시가 되면 깨어 있는 사람도 강제로 잠든다.
- 밤 정산은 서버가 한 틱 안에서 하는 **결정적 계산**이다. 같은 상태에서 정산하면 항상 같은 결과가 나온다.
- 성장, 재생, 완공이 모두 **밤 정산 때만** 일어난다(사용자 결정: 지금의 30초 재생과 5초 건설을 하루 단위로 바꾼다). 낮 동안의 상태 변화는 플레이어의 행동뿐이다.

## 사용자가 정한 것

| 항목 | 결정 |
| --- | --- |
| 장르 | 스타듀밸리 풍 협동 농장, 1~4인, 3D 탑뷰, 방 코드 입장 (기존) |
| 하루 길이 | 실시간 10분 (기존) |
| 하루 넘김 | **모두 자면 넘어간다.** 새벽 2시에 강제로 잠든다 |
| 핵심 기능 | **농사**(밭 갈기 → 심기 → 물 주기 → 수확), **출하 상자와 상점**, **제작과 도구 강화** |
| 소유 | **돈은 농장 공용, 아이템은 개인** |
| 기존 채집과 건설 | **하루 단위로 바꾼다.** 고갈된 나무/돌은 밤 정산 때 다시 생기고, 지은 집은 다음 날 아침 완공 |
| 맵 | **작은 맵 여러 개를 이어 붙인다.** 맵 가장자리의 출입구로 걸어가면 이웃 맵으로 넘어간다. 큰 맵 하나에서 재생 없이 탐험하는 방식은 하지 않는다 |
| 넣지 않는 것 | 체력(스태미나), 계절 (이번에 고르지 않음) |
| 저장 | 계정과 농장 저장은 이미 있다([persistence.md](persistence.md)). 새 상태(시계, 돈, 밭, 아이템, 도구)도 같은 방식으로 저장한다 |
| 위치 판정 | 서버가 판정한다. 클라이언트는 의도(방향, 행동, 대상 칸)만 보낸다 (기존) |
| 방 코드 | 숫자 6자리, 방장 이전, 빈 방 삭제 (기존) |

## 시스템별 기획

### 1. 시간과 잠

| 항목 | 기본값 | 비고 |
| --- | --- | --- |
| 하루의 시각 | 06:00 시작, 02:00 끝 | 실시간 10분 = 12,000틱. 게임 1분 = 10틱 |
| 시계 표시 | 게임 10분 단위 | 클라이언트는 서버 틱에서 시각을 계산해 표시하고, 서버가 주기적으로 맞춰 준다 |
| 잠드는 곳 | **농장 시작 집**이나 **완공된 집**의 앞(200 cm 안) | 지은 집에 쓸모가 생긴다. 집 안 실내는 없다 |
| 잠든 동안 | 이동과 행동을 하지 않는다. 깨어나기(취소)는 할 수 있다 | |
| 넘어가는 조건 | 방 안의 모든 사람이 잠듦, 또는 02:00 | 방에 없는(나간) 사람은 세지 않는다 |
| 강제로 잠들 때의 벌칙 | 없음 | 스타듀밸리식 벌칙(돈을 잃음)은 넣지 않는다. 필요하면 나중에 |
| 다음 날 아침 | 모두 06:00에 시작 위치(시작 집 앞)에서 깨어난다 | |
| 농장이 닫혀 있는 동안 | 시간은 흐르지 않는다(기존 규칙). 다시 열면 **닫힌 날, 닫힌 시각 그대로** 이어서 한다 | 시계를 저장한다 |
| 게스트 방(임시 방) | 같은 하루 규칙으로 돌지만 저장하지 않는다 | |

### 2. 농사

| 항목 | 기본값 | 비고 |
| --- | --- | --- |
| 칸 | 100 x 100 cm 격자(집 짓기 배치 격자와 같다) | 밭은 칸 단위 상태다 |
| 밭을 둘 수 있는 곳 | **농장 맵**의 빈 칸(출입구 앞은 제외) | 맵을 나누기 전(조각 2.5 이전)에는 지금의 건설 구역(맵 중앙 사방 1,200 cm) 안 |
| 행동 거리 | 내 위치에서 칸 중심까지 150 cm 이내 | 서버 위치 기준 |
| 도구 | 괭이(밭 갈기), 물뿌리개(물 주기), 도끼(나무), 곡괭이(돌), 손(수확, 심기) | **도구는 처음부터 모두 갖고 있고** 아이템 칸을 차지하지 않는다. 물뿌리개는 물을 채우지 않아도 된다 |
| 물 | 물을 준 칸의 작물만 그날 밤 하루 자란다. 밤 정산 뒤 모든 칸의 물이 마른다 | 물을 안 주면 자라지 않을 뿐 죽지 않는다 |
| 작물 | 당근: 4일, 감자: 6일, 토마토: 8일 뒤 첫 수확 + 이후 3일마다 다시 수확 | 이름과 일수는 임의. 계절이 없어 언제든 심는다 |
| 수확 | 다 자란 작물을 손으로 거둔다. 한 칸에서 1개 | 품질 등급은 없다 |
| 갈아 둔 빈 밭 | 원래 땅으로 돌아가지 않는다 | 되돌아가는 규칙은 넣지 않는다 |
| 이동 | 밭과 작물은 이동을 막지 않는다 | 집, 스프링클러, 살아 있는 나무/돌은 막는다(기존 충돌 규칙) |

### 3. 출하 상자와 상점 (경제)

| 항목 | 기본값 | 비고 |
| --- | --- | --- |
| 돈 | **농장 공용 지갑 하나**, 단위는 골드 | 모두가 벌고 모두가 쓴다 |
| 처음 돈 | 500골드 | 새 농장(또는 게스트 방)을 만들 때 |
| 처음 지급 | 당근 씨앗 15개(농장을 처음 만든 사람) | 상점이 없는 조각에서도 농사를 시작할 수 있게 |
| 출하 상자 | 시작 집 옆에 고정 1개. 넣은 아이템은 내 인벤토리에서 빠지고 **밤 정산 때 팔려** 공용 지갑에 들어간다 | 넣은 것을 되찾기는 없다 |
| 상점 | **마을 맵**의 고정 상점 1곳(상인 수레 같은 물체). 영업 시간 없이 언제든 연다 | 사람(주민) 없이 물체를 눌러 쓴다. 마을 맵은 경제 조각(4)에서 생긴다 |
| 상점에서 하는 일 | 씨앗 사기, 도구 강화 | 팔기는 출하 상자로만 한다 |
| 가격 | 당근 씨앗 20 / 판매 35, 감자 씨앗 50 / 판매 110, 토마토 씨앗 60 / 판매 40(수확마다) | 임의. 측정이 아니라 "하루 몇 칸이면 남는가"를 맞춘 값이라 플레이해 보고 바꾼다 |
| 판매 가능 | 작물, 목재(2), 석재(2) | 괄호는 개당 가격 |

### 4. 제작과 도구 강화

| 항목 | 기본값 | 비고 |
| --- | --- | --- |
| 도구 강화 | 괭이, 물뿌리개, 도끼, 곡괭이 각각 3단계(1 → 2 → 3) | 상점에서 즉시 강화. 강화하는 동안 도구를 못 쓰는 대기 일수는 없다 |
| 강화 효과 | 괭이와 물뿌리개는 칸 수(1칸 → 앞으로 3칸 → 3x3), 도끼와 곡괭이는 한 번에 깎는 체력(1 → 2 → 3) | |
| 강화 비용 | 2단계: 500골드 + 석재 25, 3단계: 2,000골드 + 석재 50 | 임의 |
| 도구 소유 | **개인**(아이템이 개인인 것과 맞춘다). 농장마다 따로 | (농장, 계정)별로 저장 |
| 제작 | 인벤토리에서 바로 만든다(작업대 없음) | |
| 제작 목록 | **스프링클러**: 목재 20 + 석재 10, 밤 정산 때 위아래좌우 4칸에 물을 준다. 놓으면 1칸을 차지하고 이동을 막는다 | 처음에는 이것 하나. 농사 자동화와 밤 정산을 연결하는 서버 의미가 있는 것부터 |
| 집 짓기 | 지금처럼 목재 20 + 석재 10, 개인 인벤토리에서 낸다. **다음 날 아침 완공**, 완공된 집 앞에서 잘 수 있다 | 기존 조각 1을 하루 단위로 바꾼다 |

### 5. 채집 (기존 기능을 하루 단위로)

- 나무 30개, 돌 20개, 체력, 거리 200 cm, 쿨다운 0.5초는 그대로다. 맵을 나누면 나무는 **숲 맵**, 돌은 **채석장 맵**에 있다.
- **고갈된 노드는 30초 뒤가 아니라 밤 정산 때 모두 다시 생긴다**(새 자리 고르기와 구역 규칙은 그대로). 하루에 모을 수 있는 양이 정해진다(기본값에서 목재 150, 석재 160).
- 도끼와 곡괭이 강화가 한 번에 깎는 체력을 늘린다.
- 노드 상태는 지금처럼 저장하지 않는다. 다음 날 아침이면 어차피 다 다시 생기므로, 하루 중간에 농장을 닫았다 열면 그날 깎은 노드가 되살아나는 것을 한계로 적는다.

### 6. 아이템

- 지금의 `wood`/`stone` 두 칸을 **일반 아이템 표(아이템 번호, 개수)**로 바꾼다. 목재, 석재, 씨앗 3종, 작물 3종, 스프링클러가 첫 목록이다.
- 칸 수 제한은 없다(종류별 개수만, 한 종류 최대 999). 단축 칸(핫바)은 클라이언트의 표시일 뿐 서버는 "지금 손에 든 것"을 행동 요청의 인자로 받는다.
- 아이템은 개인 것이고 플레이어끼리 주고받기는 없다. 공용 상자도 없다.
- 프로토콜은 하위 호환으로 더하고 기존 `wood`, `stone` 필드는 한동안 같이 채운다(content-roadmap.md의 이월 부채).

## 맵 (사용자 결정: 작은 맵 여러 개, 구성과 값은 기본값)

한 방(농장)은 **맵 여러 개**로 이루어진다. 맵마다 지금과 같은 5,000 x 5,000 cm이고, 가장자리의 출입구로 걸어가면 이웃 맵으로 넘어간다. 맵마다 역할이 분명하게 나뉜다.

```
              (광산: 나중 후보)
                     │
   숲 ─────────── 농장 ─────────── 채석장
                     │
                   마을 (조각 4)
```

| 맵 | 들어가는 것 | 저장 |
| --- | --- | --- |
| **농장** | 시작 집, 출하 상자, 밭, 지은 집, 스프링클러. 자원 노드는 없다 | 저장한다(집, 밭, 스프링클러, 출하 상자 내용) |
| **숲** | 나무 30개 | 저장하지 않는다(밤마다 다시 생긴다) |
| **채석장** | 돌 20개 | 저장하지 않는다 |
| **마을** | 상점 | 저장할 것 없음. 경제 조각(4)에서 생긴다 |
| 광산 (나중 후보) | 들어갈 때마다 시드로 새로 만드는 층. 내려갈수록 다른 돌과 광석 | 저장하지 않는다. "탐험" 느낌은 이 맵 하나로 낸다(열린 결정) |

| 규칙 | 기본값 | 비고 |
| --- | --- | --- |
| 맵 크기 | 맵마다 5,000 x 5,000 cm | 지금의 이동, 충돌, 노드 배치 코드를 맵마다 그대로 쓴다 |
| 출입구 | 이웃과 맞닿은 가장자리 가운데의 폭 400 cm 통로. 몸 중심이 통로의 가장자리 50 cm 안으로 들어가면 넘어간다 | 서버가 판정한다 |
| 넘어간 뒤 위치 | 이웃 맵의 맞은편 출입구에서 150 cm 안쪽. 이동 방향은 유지한다 | 계속 걸어 들어가는 느낌 |
| 출입구 앞 | 출입구에서 300 cm 안에는 짓거나 밭을 갈거나 노드를 두지 않는다 | 길이 막히지 않게 |
| 서로 다른 맵 | 4명이 서로 다른 맵에 있어도 된다. 스냅샷은 **같은 맵에 있는 사람만** 받는다 | 맵에 따라 받는 사람을 나누는 가장 단순한 관심 영역 관리 |
| 하루와 맵 | 밤 정산은 방의 모든 맵에서 돈다. 아침에는 모두 **농장 맵**의 시작 집 앞에서 깬다 | |
| 잠드는 곳 | 농장 맵의 시작 집이나 완공된 집 앞(지금 규칙 그대로) | |

시작 집, 출하 상자, 상점은 모든 농장에서 같은 자리에 있는 고정 물체이고, 이동을 막으며, 저장하지 않는다(설정에서 다시 만든다). 맵을 나누면 지금의 "구역 분리"(건설 구역/자원 구역)는 필요 없어진다. 건물과 밭은 농장 맵에만, 노드는 숲과 채석장에만 있기 때문이다.

상세 규칙(출입구 판정, 맵별 알림, 프로토콜, 완료 기준)은 [content-maps.md](content-maps.md)가 기준이다. 농장 맵은 구역 제한 없이 맵 전체에 지을 수 있다(출입구 앞 제외).

**맵을 나누기 전(조각 2.5 이전)까지는** 지금처럼 맵 하나에 구역을 나눈 구성으로 동작한다(조각 2는 이 구성으로 구현한다).

| 맵 여러 개 | 방 안에 맵(월드) 여러 개, 출입구 판정과 맵 이동, 맵별 스냅샷과 알림(같은 맵 사람만), 맵별 노드와 구조물, 밤 정산을 맵마다 | `World`, `ResourceField`, `StructureSet`이 방에 하나씩. 맵마다 하나씩 두는 구조로 바꾼다 |
| 하루와 잠 | 방 시계, 잠 상태, "모두 잠듦" 판정, 밤 정산 단계(정해진 순서의 결정적 계산) | 20Hz 틱, 틱 번호 |
| 밤 정산 | 성장, 물 마름, 판매, 재생, 완공, 저장을 한 곳에서 정해진 순서로 | 틱마다 도는 재생/완공(하루 단위로 옮긴다) |
| 농사 | 칸 단위 밭 상태, 칸 대상 행동 판정(거리, 구역, 겹침), 바뀐 칸 알림 | 격자 맞춤, 겹침 판정, 구역, 바뀐 것만 알리는 방식(`ResourceUpdate`, `StructureUpdate`) |
| 경제 | 공용 지갑, 출하 상자 내용, 가격표, 구매 판정 | 없음 |
| 제작과 강화 | 레시피, 도구 단계(개인), 스프링클러(장애물 + 밤 정산) | 구조물과 충돌 |
| 아이템 | 일반 아이템 표 | `wood`/`stone` 두 칸 |
| 저장 | 시계, 돈, 밭, 출하 상자, 아이템, 도구, 스프링클러를 농장 저장에 더한다. **밤 정산이 저장 시점**이 된다 | 쓰기 대기열(`FarmPersistence`), 절대값 upsert, 트랜잭션 저장 |

서버의 원칙은 그대로다. 게임 규칙(`Room`, `World` 등)은 소켓, 시계, DB를 모르고 틱 번호로만 시간을 안다. 밤 정산도 순수 계산이라 소켓 없이 시험한다.

## 클라이언트(Unreal)에 주는 영향

- 시계 HUD, 잠자기와 깨어나기, 하루가 넘어갈 때의 화면 전환
- 맵마다 레벨(또는 한 레벨 안의 떨어진 구역), 맵을 넘어갈 때의 전환, 다른 사람이 어느 맵에 있는지 표시
- 손에 든 것 고르기(단축 칸), 대상 칸 표시(마우스나 앞 칸)
- 밭 칸, 작물 성장 단계, 물 준 칸의 표시
- 출하 상자, 상점 화면(씨앗 사기, 도구 강화), 공용 돈 표시
- 제작 화면(스프링클러)
- 기존 순서대로 만든다: S0 서버 → S1 Unreal C++ → S2 MCP 에셋 → S3 사람의 PIE 확인

## 넣지 않는 것 (이번 기획 범위 밖)

| 빼는 것 | 이유 |
| --- | --- |
| 체력(스태미나), 계절, 날씨(비) | 이번에 고르지 않음. 계절과 날씨는 밤 정산에 규칙 하나씩 더하는 모양이라 나중에 붙이기 쉽다 |
| 주민, 호감도, 대화, 축제, 결혼 | 클라이언트 콘텐츠의 양에 비해 서버가 판정할 것이 적다 |
| 낚시, 광산, 전투, 몬스터 | 전투는 서버 쪽 몬스터 AI와 판정이 필요해 크다. 원하면 별도 기획 |
| 동물과 축사 | 다음 후보. 밤 정산과 잘 맞는다 |
| 큰 맵 하나와 재생 없는 탐험 | 사용자가 맵 여러 개를 골랐다. 큰 맵은 청크 단위 전송(입장 응답이 프레임 상한 65,536바이트를 넘음), 절차적 생성, 바뀐 칸 전부의 저장이 필요해 크고, "밤마다 재생"과도 맞지 않는다. 탐험은 광산 맵(나중 후보)으로 낸다 |
| 공용 상자, 아이템 주고받기, 품질 등급, 작물 시듦 | 단순하게 시작한다 |
| 한 판의 끝(승리 조건) | 스타듀밸리처럼 끝이 없다. 공동 목표가 필요하면 나중에 (열린 결정) |

## 열린 결정 (기본값으로 진행하고, 바꾸고 싶으면 알려 주세요)

| 결정 | 기본값 | 바꾸면 |
| --- | --- | --- |
| 공동 목표 | 없음 | "농장 목표 게시판"(돈 N 모으기, 작물 N개 출하) 같은 것을 경제 조각에 더한다 |
| 잠드는 곳 | 시작 집이나 완공된 집 앞 | 어디서나 잘 수 있게 하면 판정이 하나 준다 |
| 다시 열 때의 시각 | 닫힌 시각 그대로 | "닫으면 그날은 끝, 다시 열면 다음 날 아침"으로 하면 밤 정산을 닫을 때 한 번 더 해야 한다 |
| 가격과 성장 일수 | 위 표 | `PlayConfig` 한 곳 |
| 도구 소유 | 개인 | 농장 공용으로 하면 강화 한 번이 모두에게 적용된다 |
| 광산 맵 | 나중 후보(넣지 않음) | 넣으면 층 생성 규칙, 광석과 도구 단계의 관계를 정한다 |
| 맵 배치 | 농장 가운데, 숲 서쪽, 채석장 동쪽, 마을 남쪽 | 출입구 위치만 바뀐다 |

## 지난 기획에서 바뀐 것

- 처음 기획의 최소 구현(방 코드, 같은 맵에서 움직이는 모습)과 확장 5번(채집), 6번(집 짓기)은 구현되었다([stage4.md](stage4.md), [stage4-gather.md](stage4-gather.md), [content-roadmap.md](content-roadmap.md) 조각 1). 확장 7번(농작물)은 이 기획의 농사로 구체화했다.
- "월드 저장은 확장에서"와 "닉네임만, 계정 없음"은 계정과 농장 저장([persistence.md](persistence.md))으로 바뀌었다. 게스트는 그대로 있다.
- 시간의 기본 단위가 틱(초)에서 하루로 바뀐다. 채집 재생(30초)과 건설 시간(5초)은 밤 정산으로 옮긴다.
- 맵 하나(5,000 x 5,000 cm)를 **같은 크기의 맵 여러 개**(농장, 숲, 채석장, 이후 마을)로 늘린다. 이동 속도, 플레이어 반지름 등 이동 규격은 그대로다([stage4.md](stage4.md)).
