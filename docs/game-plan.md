# 게임 기획 (4단계)

> 상태: **초안.** 사용자가 정한 간단한 기획을 옮기고, 서버 구조에 미치는 영향과 아직 정해지지 않은 것을 정리했다. 4단계에 들어가기 전에 목표와 완료 기준을 다시 확정한다.

## 한 줄 요약

1~4명이 한 방에 모여 같은 맵에서 함께 노는, 스타듀밸리 풍의 협동 농장 게임. 3D 탑뷰. 클라이언트는 Unreal, 서버는 이 저장소의 C++ 서버다.

## 범위

### 최소 구현 (먼저 만든다)

1. 1~4인 게임
2. 스타듀밸리 풍
3. 3D 탑뷰
4. 방 코드를 입력해 입장

즉 "방을 만들고, 방 코드로 친구가 들어오고, 같은 맵에서 서로 움직이는 모습이 보이는 것"까지다.

### 이후 확장 (최소 구현이 끝난 뒤)

5. 나무, 돌 등을 도끼나 곡괭이로 쳐서 자원 획득
6. 집 짓기
7. 농작물 키우기

## 서버 구조에 주는 영향

| 기획 | 서버에서 필요한 것 | 지금 있는 것 |
| --- | --- | --- |
| 방 코드로 입장 | 방을 만들고 코드를 발급, 코드로 찾아 입장, 최대 4명 제한, 방 수명 관리(비면 정리) | 방은 단일 `ChatRoom` 하나뿐. **방 관리자(여러 방)가 필요** |
| 1~4인이 같은 맵 | 방 단위의 게임 상태와 틱(주기적 갱신) | 틱 루프 없음 |
| 서로 움직임이 보임 | 위치 동기화 메시지, 입력 검증(속도, 범위), 상태 전송 주기와 보간 | 없음 |
| 방 안의 대화 | 방별 채팅 | 채팅은 있으나 방이 하나. 방 단위로 나누면 됨 |
| 자원 획득, 집, 농작물(확장) | 서버가 소유하는 월드 상태(자원 체력과 재생, 건물, 작물 성장 시간), 낮/밤과 시간 흐름 | 없음 |
| 월드 저장(확장) | 방/월드 상태의 DB 저장과 복원 | 채팅 기록 저장(MySQL)이 기반 |

방 코드, 틱, 위치 동기화가 최소 구현의 핵심이고, 월드 상태와 저장은 확장에서 다룬다.

## 3단계 측정과의 연결

3단계는 지금 Ping 중심으로 재지만, 이 게임의 트래픽은 "방마다 4명이 초당 수십 번 위치를 주고받는" 모양이다. 3단계에서 확정한 측정 방법과 도구(`load_client`)는 그대로 쓰고, 4단계에서 **게임과 비슷한 워크로드**(방 수, 방당 인원 4명, 위치 갱신 빈도)를 추가해 다시 잰다.

## 엔진 연동에서 먼저 확인할 위험

- **(해소됨: 스파이크 성공, [unreal-client.md](unreal-client.md))** Unreal 5.4.4에서 Protobuf 6.33.4를 빌드해 TCP로 접속하고 Ping을 왕복하는 것까지 확인했다. 아래는 스파이크 전의 위험 기록이다.
- **Unreal 클라이언트가 이 프로토콜을 말할 수 있어야 한다.** 가장 큰 미지수는 Unreal 프로젝트에서 Protobuf(C++)를 빌드해 쓰는 것이다. 본격적인 구현 전에 **작은 시험(스파이크)** 으로 먼저 확인한다: Unreal에서 TCP로 접속해 `PingRequest`를 보내고 `PingResponse`를 받는 것까지.
- 프레임 형식(길이 4바이트 + ID 2바이트 + 본문)은 Unreal 쪽에서 직접 구현해도 간단하다. Protobuf 연동이 막히면 본문 인코딩 방식을 바꿀지 따로 판단한다.

## 결정한 것

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| 위치 판정 | **서버가 판정한다.** 클라이언트는 이동 입력(방향)을 보내고 서버가 위치를 계산해 전송한다. 클라이언트 예측은 나중에 | 서버가 상태와 판정을 소유한다는 프로젝트 목표와 일치 |
| 방 코드 | **숫자만, 6자리.** 서버가 무작위로 발급하고 이미 쓰는 코드면 다시 뽑는다. 방장이 나가면 다음 사람에게 방장을 넘기고, 빈 방은 삭제 | 자릿수는 6자리로 정했다(100만 개). 바꾸기 쉽다. 앞자리가 0일 수 있으므로 문자열로 다룬다 |
| 월드 저장 | 최소 구현에서는 **저장하지 않는다**(방이 닫히면 사라짐). 확장 단계(집, 농작물)에서 저장 | |
| 플레이어 식별 | 닉네임만, 계정 없음 | |
| 틱 | 초당 20회, 위치는 방 전체 스냅샷으로 전송 | 방당 4명이라 변경분 전송이 필요 없다 |
| 맵 | 고정 맵 하나 | 서버가 이동 가능 영역을 알아야 한다(아래) |

## 정해진 것 (4단계 서버 구현에서 임의 기본값으로 정함)

1. **맵과 이동 규격:** 맵 5,000 x 5,000 cm(50 m), 이동 속도 360 cm/s(처음에는 300), 플레이어 반지름 40 cm(맵 경계에만 사용, 플레이어끼리는 충돌하지 않음). 사용자가 정하지 않아 임의로 정한 값이며 `PlayConfig` 한 곳에서 바꾼다([stage4.md](stage4.md)).
